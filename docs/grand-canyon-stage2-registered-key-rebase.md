**Source of authority:** [Control Center issue #736 ruling](https://github.com/pollackelliott/college-basketball-history/issues/736#issuecomment-7243473979). This document records the narrow implementation boundary; it creates no additional historical, owner-gate, or release authority.

The existing Grand Canyon Phase 0 and its Integration Freeze remain immutable. The individually authenticated Stage 2 census has one stale key (`usc-upstate`, stored current D-I) and 39 separate display conflicts. The one institutional identity is already settled: the March 15, 1990 USC-Spartanburg NAIA tournament opponent is the current program registered as `south-carolina-upstate`.

The new `STAGE2_CURRENT_PROGRAM_KEY_REBASE` operation **only** permits two named cells: `schools/grand-canyon/opponents.csv` line 439 `canonical_opponent_key`, and `schools/grand-canyon/source-games.csv` game `grand-canyon-1989-90-035` `normalized_opponent_key`. Each value changes from `usc-upstate` to `south-carolina-upstate`. The exact original and candidate file SHA-256s are hard-coded in the pure attestation module and originate in the independent complete-population proof on issue #736. A second source row, new registry identity, duplicate target key, altered literal/game fact, or any additional field/path fails closed.

The operation requires exact current main and onboarding predecessor SHAs; the original, independently fresh-verified Phase 0 successor and original Integration Freeze/semantic snapshot; the exact 40-blocker census and its independent fresh verification; the single current-D-I `south-carolina-upstate` registry row; and the approved Control Center ruling. The permanent transaction acquires the real serialized global Implementation lock, produces an isolated candidate with independent field-level/semantic/data validation, durably writes a hash-bound write-ahead before publication, publishes using a lease-bound target-head CAS, preserves safe recovery state if interrupted, and requires a separate fresh runner to reconstruct and verify the successor. No direct GitHub file API or force ref update is permitted.

The later `STAGE2_CENSUS` must authenticate the exact `stage2_current_program_key_rebase_successor` path and hash, verify its independent fresh proof, and preserve the original Phase 0 source authority. If its new census is blocked **solely by the 39 display conflicts**, and its dry run matches that population exactly, the already-existing guarded `STAGE2_OPPONENT_DISPLAY_NORMALIZE` may be used as a separate transaction. Neither operation alters `current_d1`, Research, shared registries, historical dates/scores/sites, or owner-gate authority.

Candidate-runtime tests must prove this original case against the immutable Phase 0 onboarding commit, archived census and key. A PR modifying tools/tests/workflows/docs only is required **before** any school mutation; CI, exact-head review, and candidate replay are mandatory. This authorization cannot be reused for another program or opponent and does not grant Gate 1, Gate 2, Preview or Production rights.
